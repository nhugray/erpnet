⚙️ Đi Sâu Vào Cơ Chế Hoạt Động Của Frappe Framework Core

Frappe Framework là nền tảng Full-stack Python & JS xây dựng theo mô hình kiến trúc điều khiển bằng siêu dữ liệu (Metadata-driven Architecture). Mọi thực thể nghiệp vụ (Kho, Hàng hóa, Đơn hàng) đều được định nghĩa thông qua khái niệm trung tâm là DocType.

🐍 1. Web Application Server (Gunicorn)
Chạy trên Python 3.11+, sử dụng mô hình Gthread worker với 2 workers và 4 threads xử lý đồng thời các HTTP Request từ trình duyệt và API. Mọi request đều khởi tạo một ngữ cảnh cục bộ frappe.local chứa thông tin phiên làm việc, người dùng đăng nhập và kết nối CSDL riêng biệt.
📡 2. Realtime Event Server (Node.js Socket.IO)
Được viết bằng Node.js, lắng nghe kênh Redis Pub/Sub. Khi bất kỳ chứng từ nào trong ERPNext được tạo hoặc cập nhật (ví dụ: Thu ngân bấm thanh toán hóa đơn POS), Frappe đẩy một thông báo vào Redis, Socket.IO lập tức bắn tín hiệu về màn hình quản trị của Quản lý chuỗi ngay tức khắc.
⏱️ 3. Bộ Lập Lịch Định Kỳ (Frappe Scheduler)
Thay thế cronjob truyền thống của Linux. Scheduler chạy nền mỗi phút kiểm tra bảng Scheduled Job Type để kích hoạt các tác vụ: tính toán tồn kho cuối ngày, kiểm tra hạn sử dụng các lô bánh, gửi email báo cáo doanh thu tự động cho quản lý mỗi 22h đêm.
👷 4. Công Nhân Xử Lý Ngầm (Background RQ Workers)
Được chia làm 3 phân luồng độc lập:
• Short: Gửi thông báo, cập nhật cache (dưới 5 giây).
• Default: Tính toán lại giá thành, lập phiếu kho.
• Long: Đồng bộ dữ liệu lớn, chạy báo cáo tài chính hàng quý hoặc chạy script mô phỏng lịch sử giao dịch.

📜 Mô Hình "Everything is a DocType" Trong Frappe

Khác với các framework truyền thống (như Django hay Spring Boot phải viết tay Model, Migration, Controller, UI View riêng), trong Frappe:

  • ✔
    JSON Schema là gốc: Khi tạo DocType Warehouse, Frappe lưu một file JSON mô tả cấu trúc trường (warehouse_name, parent_warehouse, is_group).
  • ✔
    Tự động tạo bảng SQL: Frappe ORM tự đọc file JSON và thực thi câu lệnh CREATE TABLE tabWarehouse tương ứng trong MariaDB mà lập trình viên không cần viết lệnh SQL tạo bảng.
  • ✔
    Tự sinh giao diện và API: Ngay lập tức người dùng có giao diện Form nhập liệu, danh sách List view, cây phân cấp Tree view và toàn bộ bộ REST API /api/resource/Warehouse mà không tốn thêm 1 dòng code nào.

🗄️ Đi Sâu Vào Cơ Chế Kết Nối CSDL MariaDB & Kiến Trúc Multi-Tenancy

Tìm hiểu cách thức Python kết nối vào MariaDB qua thư viện mysqlclient, quản lý pool kết nối, ánh xạ ORM và cách phân vùng dữ liệu an toàn cho từng khách hàng (Multi-tenant Architecture).

1. Cơ Chế Multi-Tenancy Dựa Trên Site (Site-Based Isolation)

Mỗi dự án trên Frappe Bench quản lý một thư mục sites/. Mỗi thư mục con đại diện cho một Site độc lập (trong dự án của chúng ta là site frontend):

# Nội dung file /home/frappe/frappe-bench/sites/frontend/site_config.json { "db_name": "_b7b120c781aea689", // Tên Database riêng biệt trong MariaDB "db_user": "_b7b120c781aea689", // Tài khoản truy cập chỉ xem được DB này "db_password": "JnYokH3TaOlGsISW", // Mật khẩu kết nối ngẫu nhiên bảo mật cao "db_type": "mariadb", "installed_apps": ["frappe", "erpnext"] }

Nguyên lý kết nối: Khi có HTTP Request đến với Hostname là frontend, Nginx gửi header X-Frappe-Site-Name: frontend. Framework sẽ tự đọc file config trên, mở kết nối an toàn vào đúng cơ sở dữ liệu của site đó. Điều này đảm bảo không có bất kỳ khả năng rò rỉ dữ liệu chéo giữa các site khác nhau.

🤖 Cơ Chế Tác Tử AI Tự Hành (AI Supply Chain Agent Workflow)

Chi tiết luồng hoạt động khép kín giữa AI Service Account, mô hình ngôn ngữ lớn (Gemini), cơ chế gọi công cụ (Tool Calling) và tạo chứng từ tự động trên ERPNext.

👀 Bước 1: Agent Quan Sát (Observe)
AI Service dùng Token HTTP gọi API:
• GET /api/resource/Bin: Lấy tồn kho hiện có của 8 cửa hàng và bếp.
• GET /api/resource/POS Invoice Item: Lấy số lượng bánh & nước bán được trong 30 ngày qua.
• GET /api/resource/Purchase Order?docstatus=0: Lấy các đơn hàng đang giao chưa về kho.
🧠 Bước 2: Phân Tích & Dự Báo (Reason)
• Tính tốc độ tiêu thụ trung bình ngày (ADD).
• Nạp yếu tố ngoại cảnh: Lễ Tết sắp tới, dự báo thời tiết lạnh ở Hà Nội (nhu cầu cà phê nóng tăng 40%), mùa mưa ở HCM.
• Tính điểm đặt hàng lại: ROP = (Lead Time × ADD) + Tồn an toàn.
• Phân rã nguyên vật liệu cần mua bằng định mức BOM.
✍️ Bước 3: Tự Động Ra Quyết Định (Act)
Gemini kích hoạt công cụ Function Calling:
• Gọi hàm create_draft_purchase_order(...).
• Gửi HTTP POST /api/resource/Purchase Order với trạng thái docstatus = 0 (Bản nháp).
• Đính kèm phần giải trình lý do rõ ràng của AI vào trường ghi chú chứng từ.
👤 Bước 4: Con Người Duyệt (Human-in-the-Loop)
• Nhân viên mua hàng hoặc Quản lý chuỗi mở ERPNext lên $\rightarrow$ Thấy thông báo có 1 bản nháp Đơn mua hàng mới do AI lập.
• Người quản lý xem lý do giải trình của AI, kiểm tra số lượng và bấm nút Submit (Duyệt).
• Đơn hàng chính thức được gửi cho Nhà cung cấp.

🛡️ 3 Rào Chắn An Toàn Đảm Bảo AI Không Gây Lỗi Hệ Thống

🔒 1. Quyền Hạn Tối Thiểu (Principle of Least Privilege)
Tài khoản AI Service chỉ được cấp quyền đọc và quyền tạo bản nháp (Draft). Tuyệt đối không cấp quyền Duyệt (Submit) hay quyền Xóa chứng từ (Delete).
📐 2. Không Bịa Đặt Số Liệu (Zero Hallucination)
Mọi công thức tính ROP, tồn kho an toàn, quy đổi BOM đều được viết bằng mã Python toán học xác định. Mô hình LLM chỉ đóng vai trò phân tích ngữ cảnh và xâu chuỗi gọi hàm.
📝 3. Truy Vết Minh Bạch (Audit Trail)
Mọi đơn hàng do AI tạo ra đều được lưu nhật ký thay đổi với tên người tạo ai_service@erpnet.vn và kèm văn bản giải trình lý do tính toán để con người đối chứng.
